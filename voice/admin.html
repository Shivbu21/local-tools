Take VoiceQ to a real phone line

The test-call panel on the previous page runs entirely in the browser (Web Speech API). To answer real phone calls, connect a telephony provider. The AI brain stays the same — only the ears and mouth change.

Option A · Twilio (works worldwide)

  1. Buy a phone number in the Twilio console.
  2. Point its Voice webhook at your server: https://your-server/voice-webhook
  3. When a call comes in, Twilio POSTs the caller details. Your server replies with TwiML — the same greeting VoiceQ speaks in the browser:
<Response>
  <Say voice="alice" language="en-IN">
    Namaste! You've reached Sharma Salon. How can I help you?
  </Say>
  <Gather input="speech" speechTimeout="auto"
          action="https://your-server/voice-webhook" method="POST" />
</Response>
  1. Twilio transcribes the caller's speech and POSTs SpeechResult to your action URL.
  2. Your server runs the same intent brain as this page (booking → hours → services → price → fallback), then replies with the next <Say> + <Gather> pair.
  3. When a booking completes, save it exactly like the browser does — the dashboard reads the same appointment list.

Option B · Exotel (popular in India)

Same idea: Exotel calls your webhook on incoming calls (CallFrom), you return a response with a speak + gather applet, and Exotel posts the transcribed speech back. The webhook contract is equivalent — swap TwiML for Exotel's applet JSON.

The webhook contract (either provider)

POST /voice-webhook
  { "From": "+919811022334", "SpeechResult": "i want to book an appointment" }

-> 200 OK, TwiML:
<Response>
  <Say>Sure, I can book that for you. What's your name?</Say>
  <Gather input="speech" action="/voice-webhook" method="POST"/>
</Response>

Keep one conversation state per CallSid / caller number (name → date → time), exactly like the booking flow in the test-call panel.
